# デザイン設計

2026-10-21 / 確定 v0.11 / Projectsを画像中心に調整。1ページ型・両テーマ・タイムラインを継続

## 1. 表現の方針

キーワードは「静か」「明瞭」「積み重ね」。Software EngineerとScrum Masterを同じ階層で扱い、制作物と考え方によって人物像を伝える。

本人の名前をH1とし、職種と1行の活動概要を添える。説明用の前置き・抽象的なキャッチコピー・同じ内容の繰り返しを削る。詳細な文言は[コピー設計](copy.md)を参照。大きなセクションは全幅の背景面と上下余白で分ける。制作物は1件ずつ独立したカード、活動は点と軸を持つタイムライン、記事は文章リストとし、情報の役割ごとにまとまりを見分けられる形にする。画像は実物のスクリーンショットが用意できたプロジェクトだけに使う。装飾用の架空UI、スキル評価グラフ、活動件数、更新を催促する表現は追加しない。

### 比較検討

| 方向 | 特徴 | 今回の判断 |
| --- | --- | --- |
| シンプルなプロフィール一覧 | 短い自己紹介と文章のリスト | 人物がすぐ伝わる。制作物を紹介する余地を広げて採用 |
| スクリーンショット中心のギャラリー | 大きな画像とタイル | 画像準備に依存するため初回の基本形にはしない |
| 編集的なポートフォリオ | 大きなメッセージ、余白、作品と文章を分節 | 推奨。少ない情報でも構成が成立する |

参考として、[Lee Robinson](https://leerob.com/)の人物紹介を先に置く構成と、[Maggie Appleton](https://maggieappleton.com/)の関心・文章を蓄積する構成を確認した（2026-10-21、公開ページの情報構造を参照）。色・寸法を模倣したものではなく、本サイトへの適用は設計判断による。

## 2. デザイントークン案

### 色

| トークン | ライト | ダーク | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#F7F8F5` | `#151B18` | 全体背景・ヘッダー |
| `surface` | `#FFFFFF` | `#1D2621` | Activity・Aboutの背景、ダイアログ |
| `card-surface` | `#FFFFFF` | `#26332B` | Projectカードの背景 |
| `card-line` | `#CBD5CD` | `#4A5D50` | Projectカードの全周枠 |
| `ink` | `#202A27` | `#EDF3EE` | 見出し・本文 |
| `muted` | `#5D6B64` | `#ADBBB1` | 日付・補助情報 |
| `accent` | `#226057` | `#93D3BE` | テキストリンク・主操作の背景 |
| `accent-hover` | `#194B44` | `#B7E5D4` | 主操作hover |
| `on-accent` | `#FFFFFF` | `#13231D` | 主操作の文字 |
| `soft` | `#EDF2ED` | `#202B24` | 補助背景 |
| `line` | `#D6DDD6` | `#3D4C42` | 装飾的な区切り線 |
| `focus` | `#226057` | `#93D3BE` | 3pxのフォーカス輪郭 |

両テーマで本文・補助文字・リンクとcanvas・surface・card-surface・softの組み合わせは4.5:1以上を目標とする。淡い罫線を操作の唯一の識別手段にしない。リンクは下線、現在位置のナビは下線と`aria-current="location"`、外部リンクは矢印と読み上げラベルを併用する。

ヘッダー右上に太陽（ライト）・月（ダーク）のアイコンボタンを並べる。2つを「表示テーマ」のグループとして扱い、選択中のボタンだけに背景面と`aria-pressed="true"`を付ける。各ボタンには「ライトモード」「ダークモード」のアクセシブル名とツールチップを付ける。表示上はアイコンだけとし、操作領域はそれぞれ44×44pxを確保する。初回はOS設定、手動切替後は保存した選択を優先する。選択前のOSテーマ変更には追従し、選択後は勝手に切り替えない。両モードを同じ情報量・操作で使えるようにする。ローカル保存が使えない場合も、そのページ内の切替は機能させる。

### 文字

- 日本語・欧文ともシステムsans-serif。`-apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif`。
- フォント外部取得を不要にする。別フォントの採用は、実画面で和文・欧文の混植を比較してから判断する。
- 本文16px / 行高1.75。長文の行長は最大42rem。補助文字14px / 行高1.6。
- Heroの氏名: デスクトップ最大56px、モバイル36px（360px未満34px）、行高1.2。`clamp()`で調整。
- セクション見出し: 26→24px。カード名: 20px。日付・肩書き・ナビゲーション・技術名などのメタ情報だけ等幅書体を使う。
- 太さは400 / 500 / 600。日本語に過剰な字間を設定しない。英語の小見出しだけ0.08emを上限とする。
- 意味上のH1は1ページに1つ。Heroの氏名をH1に、Projects / Focus / Recent Activity / Writing / About / LinksをH2にする。About内のProfile / ExperienceはH3、その下の会社名等はH4にする。

## 3. 共通UI

### セクションの境界

| セクション | 背景 | 内容のまとまり |
| --- | --- | --- |
| Home | canvas | 氏名、職種、活動概要、リンク |
| Projects | soft | 1件ずつ面を持つカード、PC4列・タブレット2列・モバイル1列 |
| Focus | canvas | 2つの専門性を並列に置き、各軸を仕様書v1.0の見出し・本文で説明する |
| Recent Activity | surface | PCは見出しとタイムラインを2列、モバイルは縦積み |
| Writing | canvas | 文章リスト。記事間の罫線は一覧内だけに使う |
| About | surface | Profile / Experienceを見出しと余白で区分 |
| Links | soft | 外部導線をページ末尾にまとめる |

背景はviewportの全幅、本文幅は最大1120pxに揃える。セクションの上下はPC64px・モバイル48pxを基本とする。見出し直前の横罫線、カード上下だけの罫線、同じ境界に連続する二重の罫線をなくす。背景の濃淡だけで情報を伝えず、見出し・余白・コンテンツ形状も併用する。

### Header / Footer

サイト名は`koukibuu3.dev`。Home / Projects / Writing / Aboutの4リンクを常時表示し、`/#home` / `/#projects` / `/#writing` / `/#about`へ同一ページ内でスクロールする。320pxでもロゴ＋テーマ操作とナビの2行に収める。ハンバーガー・ドロワーは設けない。

長い1ページの移動を支えるためHeaderを上部に追従させる。見出しの着地点はHeaderの実測高さ＋20pxを空ける。通常はスムーズスクロール、`prefers-reduced-motion`では即時移動とする。クリック後は対象見出しにフォーカスを移し、スクロール操作だけでフォーカスを奪わない。

ナビの現在位置はスクロールに追従させる。FocusとRecent ActivityはProjectsからWritingの間のため、ナビ上ではProjectsの範囲として扱う。手動スクロールではURLや履歴を増やさず、ナビクリック時だけhashを更新する。戻る・進むでアンカー位置を再現する。

本文スキップリンクを設置。Footerは名前、著作権、ページ上部へのリンクを置く。外部プロフィールの一覧はページ末尾のLinksにまとめ、About内に同じ一覧を重ねない。旧記事ページからのHeaderリンクは`/#projects`等のルート付きアンカーとする。

### ProjectCard

各Projectを背景面、全周1pxの枠、12pxの角丸、PC24px・タブレット28px・モバイル24pxの内余白を持つカードにする。4件がそれぞれ独立した制作物として見えるよう、カード間はPC20px・タブレット24px・モバイル16px空ける。カード全体を1つの詳細リンクにする。「詳細を見る」を毎回繰り返さず、右上の装飾矢印で操作を示す。カードのリンク名は制作物名と概要から構成する。名前、概要を必ず表示し、任意の開発形態・画像は存在する場合だけ加える。カード内に外部リンクや別ボタンを入れ子にしない。hoverで罫線とリンク色を変え、キーボードでは明確な輪郭を示す。

画像がある場合は16:10、実物が切れない`object-fit: contain`を基本とする。カード用画像は装飾的に重複する内容なら`alt=""`とし、詳細モーダルに画像は表示しない。同じ一覧で画像の有無が混在しても、画像のないカードに空の枠や「準備中」を作らない。画像の整備が揃うまではテキスト型で統一できる。

### WritingRow / ActivityTimeline

Writingは画像なしの文章リスト。公開日、掲載元、タイトル、任意の概要・タグを表示する。タイトルを主リンクにし、長いタイトルは省略せず折り返す。タグは初回では表示情報だけとし、フィルターを追加しない。

Recent Activityは最大4件、新しい順の縦タイムライン。`ol`で順序を表現し、各項目は日付・種別、その下にタイトルを置く。左の点を2pxの縦軸でつなぎ、最後の点より下に軸を伸ばさない。日付とタイトルは文字で読み取れるようにし、装飾の軸や点には操作・読み上げの役割を与えない。PCは見出し280pxとタイムラインを横に置き、モバイルは見出しの下へ積む。項目の間は36pxを基本とし、長いタイトルで点と日付がずれない配置にする。記事・プロジェクト・手動活動の種別と絶対日付を添える。「何日前」「最近更新がありません」やNewバッジは使わない。0件の場合はセクション全体を非表示にする。

### 外部リンク

通常は同じタブで移動する。外部矢印と読み上げ用の「外部サイト」を付ける。新しいタブを使う場合は、表示と読み上げの両方で明示し、`rel="noopener noreferrer"`を付ける。リポジトリURLやLPを推測で生成しない。

## 4. 1ページの構成 / Home

```text
追従Header: koukibuu3.dev   Home Projects Writing About   太陽 / 月

#home
  Kouki Akasaka / Software Engineer / Scrum Master
  氏名をH1 / 1行の活動概要
  GitHub / Projects / About
#projects
  4件の制作物カード → 詳細ダイアログ
Focus
  Software Design & Architecture / Team & Engineering Process
Recent Activity
  点と縦軸に沿って、日付 / 種別 / タイトル × 最大4件
#writing
  最新6件 / [過去の記事を表示]で残りを展開
#about
  Profile / Experience
Links
  GitHub / Zenn / Qiita / X
Footer
```

Heroに顔写真や背景ビジュアルを必須化しない。Featuredの別セクションと全件一覧を重複させず、Projectsの1か所へ4件をまとめる。既存のFeatured指定3件を先頭にし、残りを続ける。任意情報の多さで選択しない。

カード選択は`/?project=<slug>#projects`を基本とした同一ページ内のモーダル。操作時は起点のhashとスクロール位置を保ち、閉じると同じカードへ復帰する。画面全体の別ページ遷移は起こさない。URLの詳細は技術設計を参照。

## 5. Projects

H2「Projects」の直下に4件をPC4列・タブレット2列・モバイル1列で表示。セクションの目的を説明する文章は置かない。初期順はFeatured候補のScrumWorkbench / Salestack / G.G. Garage、続いてCore Uma。Featured指定は任意に変更でき、指定外も省略せず掲載する。

4件のため検索やタブ・カテゴリ絞り込みを設けない。LPがなくても掲載できる。

### 画像を中心にしたカード（v0.9）

- 上部はPC・タブレットで16:10、モバイルで16:9の画像面、下部は名前と短い概要。全体を1つのリンクにし、矢印は名前の右へそろえる。
- ロゴは切り抜かず中央へ配置する。ダッシュボードSVGは全体を収め、G.G. Garageの抜粋は画像面いっぱいに表示する。画像はカードだけに表示する。画像がリンク名と重複するカードではaltを空にする。
- 明るい画像面を両テーマで維持し、素材自体の反転や色変更は行わない。カード本文・外枠はテーマに追従する。
- ScrumWorkbenchとCore Umaは既存ロゴ、Salestackはユーザー提供のダッシュボードSVGを使用。G.G. Garageはユーザー提供の開発中イメージからキャラクターと床周辺だけを切り出す。HUD・マップ・部屋の全体像は含めず、配信用素材も抜粋のみとする。詳細に画像は再掲せず、元画像へのリンクや拡大導線も設けない。
- 技術タグ、公開状態、担当などの文章はこの調整で追加しない。既存の4/2/1列とプロジェクト順を維持する。
- 元画像を読み込めない場合も、名前・概要とカード操作は残す。

### 詳細ダイアログ

- デスクトップ: 最大幅760px、左右24px以上の余白、最大高`min(880px, calc(100dvh - 64px))`。
- モバイル（768px未満）: 全画面。`100dvh`とsafe-areaを考慮し、内部だけを縦スクロール。
- 常時見える上部に「閉じる」。順序は名前 → 概要 → 任意の属性 → 担当範囲 → 背景・工夫 → 外部リンク。
- 開いた時は閉じるボタンへフォーカス。Tab循環、背景inert、背景スクロール抑止、Escape、閉じる、背景クリックに対応する。
- 背景クリックはpointerdownとpointerupの両方が背景だった場合だけ閉じる。内部からドラッグして背景へ離した操作では閉じない。
- 閉じたら起点カードへフォーカス復帰。直リンクで起点がない場合はProjects見出しへ復帰する。
- 長い内容を1つの`aria-describedby`へ詰め込まず、`aria-labelledby`で名前を関連付け、内容を見出しで分ける。
- LPがあれば「公式サイトを見る」を主操作にする。その他リンクだけなら通常リンクとして配置し、空のボタンを置かない。

モーダルの名前・概要だけでも完結する。未設定の見出し、空の定義リスト、Coming Soonは出さない。画像は一覧カードだけに使用し、モーダルには画像要素・画像用の余白を設けない。

## 6. Writing

H2「Writing」の直下に公開日降順の一覧。独自記事・Zenn・Qiitaを同じ書式で表示し、掲載元だけを明示する。記事内容の新規作成フォームは持たない。

最新6件を表示し、残りはネイティブの`details`で同じセクション内に展開する。全記事のリンクは静的HTMLに含め、JSなしでも展開可能にする。6件以下なら展開操作は出さない。別の一覧ページ・ページネーション・無限スクロールは初回作らない。日付は`YYYY.MM.DD`、日付未取得の記事は末尾に置き、架空の日付を付けない。

外部取得に失敗しても保存済み一覧をそのまま表示する。取得障害の警告を一般の訪問者へ表示しない。独自記事も外部記事もない場合のみ「公開した記事は、ここにまとめていきます。」とする。

既存の独自記事ページは共通Headerへ置き換え、タイトル・公開日・タグ・本文を読みやすい幅で残す。本文末尾に`/#writing`へのリンクを設置する。記事内のコード・表だけは横スクロールを許容し、ページ全体の横スクロールは防ぐ。

## 7. About

H2「About」の下にProfile → Experienceを配置し、その後に共通Linksを置く。Profileはバックエンドを起点とした経験と現在の担当を1段落にまとめる。Philosophyの説明はFocusに集約し、同じ価値観を別の文章で繰り返さない。`#software-design`・`#team-process`はFocus内で維持する。

職歴は担当・対象プロダクト・使用技術を中心に要約する。在籍期間、雇用区分、所属と参画案件の関係は保つ。具体的な成果数値や未確認の技術は加えない。

Experienceは所属企業を主見出しにする。期間、会社名、職種、正社員／副業・業務委託、説明の順。株式会社アクティブ・ワークの内側に参画案件をインデントして置き、弁護士ドットコム株式会社を独立した雇用先に見せない。百貨店案件は匿名表記とする。

any株式会社とHOKUTOの期間の重複をそのまま表示する。縦線の長さを在籍期間の比率として扱わない。モバイルでは日付と本文を同じ列に積み、サブ案件は左罫線で所属との関係を残す。

## 8. アクセシビリティと品質

WCAG 2.2 AAを設計上の目標とし、適合を確認済みとは表明しない。ダイアログは[WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)に沿う。

- 320 / 390 / 768 / 1440pxで折り返し・操作を確認する。
- 200%文字拡大、400%ズーム時のリフロー、キーボードのみ、VoiceOverの見出し・リンク・ダイアログ読み上げを確認する。
- 主要操作の有効領域は44px以上。タイトルやボタンを固定高で切らない。
- `overflow-wrap: anywhere`で技術名・URLを折り返し、Grid子に`min-width: 0`を指定する。
- 動きは色・輪郭の変化を基本とし、必須の登場アニメーションを設けない。追加する場合も`prefers-reduced-motion`で抑制する。
- JSなしでも1ページの全セクション、作品の名前・概要、記事リンク、外部リンクを読める。Projectsはカードのアンカー先に簡潔な詳細をサーバー出力する（技術設計参照）。

## 9. モックの扱い

[操作モック](prototype/index.html)は全画面の文字組みと遷移を比較できる設計資料。記事本文移植、画像、実際の取得処理、SEOは本実装で検証する。実物の画面を捏造せず、画像のない状態を基本としている。

# 仕様の変更: 1ページ型・テーマと情報の境界・文体

2026-10-21 / ユーザー追加指示を反映

## 確定した変更

1. ポートフォリオは1ページ型にする。Home / Projects / Writing / Aboutは同じ`/`内のセクションとし、ナビをクリックすると対象までスクロールする。
2. ライトモードとダークモードを用意し、右上に太陽・月のアイコンを並べて選択する。
3. Recent Activityはタイムライン形式にする。
4. Projectsは1件ごとにカードとし、全体の線中心の区切りによる曖昧な境界を解消する。
5. 説明的な文章を減らし、エンジニアの制作物・関心・担当経験が端的に伝わる表現にする。

この変更は当初の[仕様書v1.0](requirements-v1.md)の複数ページ構成と、設計案v0.1のライトのみの方針に優先する。原本は変更せず、現行の設計書・モックをv0.11へ更新する。

## 変更に伴う設計判断

- URLは`/#home` / `/#projects` / `/#writing` / `/#about`。4ページへの分割は行わない。
- Projectsは1か所に4件をまとめ、Featuredの3件を先頭にする。Homeの代表作と全件一覧を重複させない。
- Projectsの詳細モーダルは維持する。共有URLは`/?project=<slug>#projects`、操作時は起点のhash・スクロール位置を保つ。
- Writingの過去記事は同じページで展開する。独自記事本文は既存の`/articles/<id>`を維持する。1ページ化の対象はポートフォリオの情報ページで、既存記事のURL保存方針は継続する。
- AboutはProfile / Experienceとし、Philosophyの内容はFocusへ統合する。重複した名前・肩書きの再掲と説明文を減らす。
- 外部リンクの見出しはLinks（アンカーIDは`connect`を維持）。
- Heroは氏名をH1、職種と1行の活動概要を添える。セクションを説明する前置きは置かない。
- ヘッダーは追従し、対象の見出しが隠れない余白を確保する。動きを抑える設定では即時スクロールする。
- テーマは初回OS設定に従い、手動選択を保存して以後優先する。OS自動／ライト／ダークの3択UIは追加せず、太陽・月の独立した2つのアイコンボタンで明示的に選ぶ。選択中のアイコンは背景面と`aria-pressed`で示す。
- Projectsカードは背景面・12〜16pxの角丸・全周の枠・内余白を持つ。セクションは全幅の背景面を切り替え、線だけに境界を頼らない。
- Recent Activityは新しい順の縦タイムラインとし、日付・種別・内容を点と軸に沿って配置する。
- トップページのcanonical・OGPは1組にする。セクションやプロジェクトqueryを別の検索ページとして扱わない。

公開内容・記事保存・画像整備など、当初の仕様にある残確認は継続する。

## 追加調整（v0.5）

- Projectsは1024px以上で4カラム、768〜1023pxで2カラム、767px以下で1カラムとする。
- DM送信業務、SES参画の前置き、プロセス・協働改善への関心、個人開発の紹介について指定された文を削除する。画面の短縮表現からも同趣旨の部分を削る。提供仕様書の原本は保管を継続する。

## Focusの補足（v0.6）

Focusの2軸はそれぞれ2文とし、ドメインモデリングから設計を考える姿勢と、複数チームのスクラム実践を支援する役割を伝える。v0.5で削除した4文・同趣旨の関心表明は戻さない。

## Focusの原文復元（v0.7）

ユーザーの最新指定により、Focusの2つの見出し・本文を仕様書v1.0の原文へ戻す。v0.6の2文への要約方針より、この復元を優先する。1ページ型・テーマ・PC4カラムと、他セクションの文章削除は維持する。

## Core Umaの説明訂正（v0.8）

Core Umaは「食品・飲料の口コミサービス」とする。ユーザーの訂正と開発チャット・既存設計資料の照合に基づき、原本にある競馬関連という分類よりこちらを優先する。カード・詳細ダイアログ・JavaScript無効時の表示・移行表に反映する。確認元は[説明訂正の記録](evidence/core-uma-content-review.md)を参照。

## Projectsの画像中心の表示（v0.9）

ユーザーの指定により、カード上部に実画面または既存ロゴ、下部に名前と概要を置く。PC4カラム・カード単位の操作・詳細ダイアログは維持する。画像を設定したプロジェクトでは詳細内で画像全体を表示する。G.G. Garageの画像が未確定の間は名前の文字表現とし、公式ロゴを捏造しない。素材の確認元と検証は[Projectsの画像表示確認](evidence/projects-visual-review.md)を参照。

## Projectsの素材指定（v0.10）

- Salestackはユーザー提供の`hero-dashboard.svg`へ差し替える。ダッシュボードのイメージとして扱い、実画面とは表記しない。
- G.G. Garageはユーザー提供の開発中イメージを一部抜粋して使う。キャラクターと周辺の床・小物だけに絞り、全体像を伝える表示にはしない。カード・詳細のどちらにも切り出した画像だけを配信する。
- 生成による描き直しは採用せず、元画像と同一の画素を切り出す。素材と確認は[素材差し替えの記録](evidence/project-assets-review.md)を参照。

## 詳細モーダルの画像を削除（v0.11）

ユーザー指定により、全プロジェクトで画像は一覧カードだけに表示し、詳細モーダルには再掲しない。モーダル内の画像要素・画像同期処理・専用スタイルを削除する。この方針はv0.9・v0.10の詳細画像表示に優先する。

## デザイン確定・本実装（2026-10-21）

ユーザーの承認によりv0.11を確定デザインとする。本体へ実装し、4記事の保存と外部記事のスナップショット化、URL・テーマ・モーダル・RSS等の互換処理を行う。モックは比較用に保持する。確認結果は[実装の確認記録](evidence/implementation-review.md)を参照。

## Qastの担当説明の修正（2026-10-21）

ユーザーの指摘により、any株式会社の説明を「『Qast』の開発に携わり、複数チームのスクラムマスターを担当。」へ修正する。プロダクト全体の設計・開発を率いると読める表現を避け、本体と比較用モックに反映する。提供仕様書の原本は維持する。

## Projectsの詳細表示を見送り（2026-10-21）

ユーザー指定により、今回のリリースはProjectsを画像・名前・概要の静的なカードとし、モーダル・詳細リンク・矢印・ホバー強調・JavaScript無効時の代替詳細を表示しない。旧`?project=...`でもモーダルを開かず、旧`#project-...`はProjects一覧へ移す。既存のモーダル設計は再検討用に保持するが、今回のリリースには適用しない。比較用モックはv0.11の記録として保持する。
